¿Qué configuración de 'cross-subnet' permite Calico aplicar de forma selectiva, combinando el rendimiento del enrutamiento nativo cuando es posible con la flexibilidad de encapsulación solo cuando realmente se necesita?

Permite que Calico use enrutamiento nativo sin encapsulación cuando dos nodos están en la misma subred (donde el tráfico directo funciona bien), pero recurra automáticamente a la encapsulación (IP-in-IP o VXLAN) específicamente cuando el tráfico necesita cruzar entre subredes distintas donde el enrutamiento directo no es viable
El modo cross-subnet obliga a usar encapsulación para absolutamente todo el tráfico del cluster, sin ninguna excepción real donde se use enrutamiento nativo sin encapsulación bajo ninguna circunstancia
Solo es relevante esta configuración si el cluster tiene exactamente una única subred en total, sin ninguna necesidad real de considerar tráfico que cruce entre subredes distintas
Cross-subnet networking elimina por completo la necesidad de tener cualquier tipo de backend de encapsulación configurado (como IP-in-IP o VXLAN) disponible como respaldo para el cluster

¿Por qué usar encapsulación de forma selectiva (solo para tráfico entre subredes) en vez de encapsular absolutamente todo el tráfico del cluster ofrece un mejor balance entre rendimiento y compatibilidad de red?

Pista: la mayoría del tráfico real dentro de un cluster podría ocurrir entre nodos de la misma subred, donde el enrutamiento nativo sin encapsulación ofrece el mejor rendimiento posible; encapsular absolutamente todo el tráfico sin distinción desperdiciaría ese beneficio de rendimiento incluso en los casos donde no era realmente necesario, mientras aplicar encapsulación solo de forma selectiva para el tráfico que efectivamente cruza entre subredes distintas preserva el rendimiento óptimo para la mayoría del tráfico, usando encapsulación únicamente donde realmente se requiere.
