¿Qué concepto describe una 'red overlay' como la que Flannel construye sobre la infraestructura de red física existente de un cluster?

Una red virtual construida encima de la red física subyacente, donde el tráfico entre Pods se encapsula dentro de paquetes que viajan por la red física existente, permitiendo que los Pods se comuniquen como si estuvieran en la misma red local aunque físicamente estén en nodos distintos conectados por una red más compleja
Una red overlay reemplaza por completo la necesidad de tener cualquier tipo de red física real conectando los distintos nodos del cluster entre sí
Solo es relevante usar una red overlay si el cluster tiene exactamente un único nodo en total, sin ninguna necesidad real de conectar múltiples nodos distintos entre sí
El tráfico en una red overlay nunca se encapsula de ninguna forma, viajando siempre exactamente igual que el tráfico de red física normal sin ninguna capa adicional

Flannel · Lección 06

¿Por qué una red overlay permite que Flannel funcione sobre infraestructuras de red muy distintas (cloud, on-premise, distintos proveedores) sin necesitar que esa infraestructura subyacente tenga ninguna configuración especial previa?

Pista: como el tráfico de la red overlay se encapsula dentro de paquetes estándar que la red física subyacente ya sabe manejar sin ningún requisito especial, esa red física (sin importar si es de un proveedor cloud específico, on-premise, o cualquier otro entorno) simplemente transporta esos paquetes encapsulados normalmente; esa abstracción es precisamente lo que permite que Flannel funcione de forma consistente sobre infraestructuras de red físicas muy distintas entre sí, sin requerir una configuración especial previa en cada una.
